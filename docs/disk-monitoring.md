# Мониторинг места и Telegram

## Что отслеживается

Все смонтированные постоянные файловые системы обнаруживаются автоматически:
системные разделы, отдельные `/home`, `/var`, `/mnt` и подключённые внешние диски.
Повторные точки монтирования одного устройства не дублируются. Исключены RAM/tmpfs,
служебные файловые системы, loop-образы Snap и read-only ISO. Разделы без файловой
системы или без монтирования не имеют измеряемого свободного места и не показываются.
Новые монтирования подхватываются следующим циклом; отключённые диски исчезают из
актуальных показателей. Ручное добавление путей больше не требуется.

В systemd работает отдельный `router-disks.timer` (30 секунд) и короткоживущий
`router-disks.service`: тот же владелец данных, пустой список capabilities,
запрещённая сеть и read-only доступ к файловым системам. Он записывает только
`/run/router-disks/snapshot.json`. Основной Router читает этот снимок через
`ROUTER_DISK_SNAPSHOT`; его `ProtectHome=tmpfs` и ограничения записи не ослаблены.
Нужны оба unit-файла из `deploy/` и включённый timer. Снимок старше двух минут
не используется для тревог, интерфейс показывает ошибку сборщика.

При обычном запуске без `ROUTER_DISK_SNAPSHOT` диски обнаруживаются непосредственно
процессом Router. Старые дополнительные пути поддерживаются в конфигурации, но
не нужны для автоматического обнаружения и не редактируются в веб-форме.

Измеряется свободное место файловой системы по пути, а не размер папки.
Путь должен существовать и быть доступен пользователю, запускающему роутер.
Недоступный путь отображается в обзоре с предупреждением; старые значения
не выдаются за актуальные и не используются для тревог. Статистика обновляется
фоновым сборщиком; открытие нескольких вкладок не запускает повторный сбор.

## Настройка уведомлений

1. Введите токен бота и ID получателей, включите отправку уведомлений.
2. Включите «Уведомлять о заполнении».
3. Выберите предупреждающий и критический пороги и интервал напоминаний.
4. Сохраните настройки и отправьте тестовое сообщение.

Сводка над формой показывает, включена ли отправка, есть ли токен и получатели,
действуют ли тихие часы, время проверки и последней отправки. Ошибки доставки
показываются отдельно. Список дисков содержит фактическое заполнение и
недоступные пути. Он обновляется без перезаписи несохранённых полей формы.
Кнопка «Тест заполнения в Telegram» отправляет текущие показатели с пометкой
«не авария», не меняя состояние тревог. Этот явный тест работает независимо
от тихих часов и порогов. Без свежих измерений сообщение не отправляется.

По умолчанию пороги составляют 85% и 95%, напоминание приходит через 6 часов.
Проверка выполняется раз в минуту независимо от открытой панели. Для отправки
сообщений нужен исходящий HTTPS-доступ к Telegram. Публичный webhook нужен
для входящих команд, но не для отправки предупреждений.

Измерение дисков выполняется в отдельном цикле: медленные проверки SSH,
процессора или других показателей не задерживают обновление места на дисках.

При пересечении порога приходит сообщение с именем сервера, путём, процентом
заполнения, свободным и общим объёмом. Переход на критический уровень отправляется
сразу, без ожидания очередного напоминания. Для защиты от колебаний критическое
состояние снимается ниже критического порога минус 3 процентных пункта,
предупреждение снимается ниже предупредительного порога минус 5 пунктов.
После освобождения места отправляется отдельное сообщение.

Тихие часы учитываются по часовому поясу сервера, в том числе для критических
сообщений. После их окончания проверяется актуальное состояние. Одинаковые
начальный и конечный часы означают тишину круглосуточно.

При ошибке Telegram отправка повторяется на следующей проверке. Учёт доставки
ведётся отдельно для каждого получателя: ошибка одного чата не вызывает
повторную отправку всем остальным. Состояние отправки хранится в памяти:
после перезапуска текущая проблема может быть сообщена заново. Сами настройки
сохраняются на диске атомарно; ошибка сохранения показывается в панели.

## Интерфейс и локальная проверка

Общая навигация, светлая/тёмная темы, поиск маршрутов и адаптивная сетка
статистики доступны на всех размерах экрана. Свободное расположение виджетов
сохранено как отдельный режим для широких экранов. Переключение темы и
расположение запоминаются в браузере. Иконки Lucide 0.468.0 поставляются
локально; лицензия находится в `internal/panel/static/icons/LICENSE`.

Для изолированного просмотра можно запустить роутер с `ROUTER_PANEL_ONLY=1`
и `PANEL_ADDR=127.0.0.1:8162`. Этот режим не открывает прокси-порты 80/443,
но использует обычные локальные файлы настроек. Для тестов нужен отдельный
рабочий каталог с копией `internal/panel/static` и `internal/panel/templates`,
тестовыми `ADMIN_USER` и `ADMIN_PASS`, без рабочих секретов и заданий бэкапа.
Не включайте этот режим на рабочем роутере.

Проверки: `go test ./...`, `go vet ./...`; отдельно проверяется интерфейс
в браузере на мобильных и настольных размерах в обеих темах. В тестах Telegram
заменён локальным транспортом, реальные сообщения не отправляются.

## Перед публикацией

Переключатели обслуживания применяют подтверждённое сервером состояние без
перезагрузки страницы. При ошибке сохранения значение откатывается и показывается
сообщение. Правила записываются через временный файл и атомарную замену.
Проверки доступности сайтов больше не удерживают блокировку правил во время
сетевого ожидания. Чтение правил возвращает независимые снимки.

Маршруты на локальный адрес панели (`PANEL_ADDR`) исключены из обслуживания,
чтобы не заблокировать доступ к управлению. Их собственный переключатель
недоступен. Это не обходит вход в аккаунт: панель сохраняет свою авторизацию.
Исключение распознаёт локальное HTTP-подключение к порту панели; произвольный
удалённый сервер на том же порту исключением не является.

Отдельно фиксируйте три состояния: изменения в локальном проекте, коммит на
GitHub и установленная версия на сервере. Обновление рабочего роутера требует
согласования, проверки текущего Git-состояния и способа запуска, резервной копии
и возможности отката. Не потеряйте исправление HTTPS/WebDAV для WorkService
из коммита `603583d`; оно уже входит в исходную версию этого обновления.
