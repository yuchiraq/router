# Проверка безопасности Router, 2 ноября 2026

## Что проверено и исправлено

- Вход: отказ при отсутствующем/повреждённом хранилище администратора, отсутствие стандартного пароля, ограничение попыток и параллельных bcrypt-проверок. Ошибка генерации сессии не создаёт токен.
- Сессии: HttpOnly, SameSite=Strict, Secure для HTTPS, срок 24 часа; изменение учётной записи отзывает прежние сессии. Пароль при изменении: 12–72 байта. Существующие пароли не сбрасываются автоматически; старый короткий пароль следует заменить.
- Изменяющие запросы: проверка Origin и Fetch Metadata, ограничение размера. CLI-клиенту без Origin нужен `X-Router-Request: 1` и действующая сессия. Этот заголовок не заменяет авторизацию.
- Публичный прокси не доверяет присланным X-Forwarded-For, X-Real-IP и CF-Connecting-IP. Перезапись метаданных выполняется после удаления hop-by-hop заголовков. Панель доверяет forwarding-заголовкам только от loopback; её порт должен оставаться на localhost.
- Заглушка проверена для разных HTTP-методов и закодированных путей: запросы не достигают upstream. Публичные ресурсы ограничены списком; статус раскрывает только доступность. Это не закрывает прямые порты сайтов: их нужно ограничивать отдельно.
- Telegram webhook без секрета закрыт. Сообщения принимаются только из разрешённых чатов. Пустой список GPT-чатов больше не означает доступ для всех. Необходимо задать webhook secret также при регистрации webhook в Telegram.
- CSP запрещает inline JavaScript, встраивание страницы и объекты; скрипты вынесены в локальные файлы. Статическая раздача не показывает HTML панели, скрытые файлы, каталоги и файлы за пределами корня.
- Тайм-ауты заголовков, ограничения размера заголовков и TLS не ниже 1.2. Длительные загрузки WebDAV намеренно не ограничены общим WriteTimeout прокси.
- Настройки администратора/GPT сохраняются атомарно с закрытыми правами. Архивы создаются с 0600; ссылки внутри исходных папок пропускаются, выход из корня ограничен os.Root, неполная копия считается ошибкой. Архивирование папки в неё же запрещено.
- Обновлены Go и x/net, x/crypto, x/sys, x/text. `govulncheck ./...`: 0 достижимых уязвимостей и 0 уязвимостей импортируемых пакетов; в модуле остаётся advisory GO-2026-5932 о неиспользуемом OpenPGP. Сканирование является снимком состояния базы, не гарантией отсутствия неизвестных ошибок.

Прямого пути выполнения shell-команд из HTTP-параметров в проверенном коде не найдено. Это не равнозначно доказательству невозможности RCE. Администратор по назначению имеет доступ к настройкам маршрутов и резервных копий; кража его сессии остаётся существенным риском.

## Проверки

`go test ./...`, `go vet ./...`, сборка linux/amd64 без CGO; регрессионные тесты авторизации, CSRF, spoofed headers, webhook и обхода обслуживания. Проверки браузером: вход, формы, обслуживание, бэкапы, темы, 320/390/768/1440 px; проверка CSP и отсутствия ошибок JS, axe WCAG A/AA. Canvas проверен по пикселям, движению, паузе и reduced motion. Скрипты браузерных проверок и снимки находятся в отдельной локальной рабочей папке, не содержат серверных данных.

## Развёртывание systemd

Шаблон: `deploy/router.service`. Он рассчитан на существующего владельца данных `yc_162`, а не root. Это сохраняет чтение приватных исходников бэкапов с режимом 0600 без расширения их прав для других пользователей. Это не отдельная системная учётная запись: полноценное разделение резервного копирования и веб-процесса остаётся возможным следующим этапом.

- Код и бинарник: `/opt/router/releases/<commit>`, `/opt/router/current` указывает на релиз. Владелец root; служба не может менять код.
- Рабочие настройки и сертификаты: `/var/lib/router`, права каталога 0700, конфигураций 0600. Это актуальные настройки, JSON в Git-каталоге после миграции является старой копией.
- `internal` в рабочем каталоге указывает на ресурсы текущего релиза.
- Домашние каталоги скрыты. Только источники бэкапов открываются через `BindReadOnlyPaths`; папки архивов разрешаются через `ReadWritePaths` в `/etc/systemd/system/router.service.d/storage.conf`.
- При добавлении нового источника в домашней папке или назначения архива нужно дополнить этот allowlist и перезапустить службу. Одного изменения веб-формы недостаточно. Не выдавайте запись на весь `/home` или `/`.
- Единственная capability: `CAP_NET_BIND_SERVICE` для 80/443. `NoNewPrivileges`, read-only файловая система, защита ядра и фильтр системных вызовов ограничивают последствия компрометации. [Описание параметров systemd](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html).
- Порт панели 8162 и WorkService 8099 остаются на loopback. Прямые порты сайтов 8088/8089 закрываются UFW для IPv4/IPv6; доступ через HTTPS Router сохраняется. Для защиты в глубину рекомендуется впоследствии привязать сами сайты к localhost.

Управление:

```sh
sudo systemctl status router
sudo journalctl -u router -n 100 --no-pager
sudo systemctl restart router
```

Нельзя параллельно запускать `sudo go run`: порты уже заняты systemd. Обновление: commit/push, на сервере pull --ff-only, тесты/сборка, новый root-owned релиз, смена current и restart. Перед миграцией сохраняются конфигурации, сертификаты, старый бинарник и UFW. Откат выполняется из этой закрытой копии; не восстанавливайте устаревшие данные поверх новых без проверки.

## Границы проверки

Это целевой аудит Router, не полный пентест всех сайтов/ОС. Уже установленные WebSocket-соединения не разрываются переключением обслуживания. Распределённый DDoS, компрометация ОС/учётной записи, MFA и резервирование сервера не решены этим обновлением. Доступ к другим публичным службам, в частности Samba, требует отдельной проверки и согласования; в данном обновлении их правила не меняются.
